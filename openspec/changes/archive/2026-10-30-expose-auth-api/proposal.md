# Proposal: 暴露权限三方 API 与可视化管理控制台（多库表勾选授权与调用日志）

## Why

外部 AI 平台（Text-to-SQL）及三方系统需要自动化获取数仓数据，以往每个取数需求均需后端定制开发接口，响应滞后且维护成本高。本变更旨在提供一套标准化、基于多数据源与细粒度表授权隔离的只读开放 API，使外部 AI 能够安全自主地获取库表元数据并执行只读查询；同时在 DataX 智能助手中提供**可视化配置管理界面**，管理员可统一配置 API 账号、绑定多个数据源库、通过交互式表列表勾选控制授权、管理 IP 白名单与限流，并对全链路调用日志进行实时审计与明细穿透。

业务领域（如出租网约、驾培监管、国盛车辆等）在数仓表名与表中文注释中已天然具备明确区分，因此账号层面无需强行绑死单一 `domainCode`，转而支持灵活的多库与多表权限绑定。

## What Changes

- **新增三方接口账号与权限控制**：基于企业级 `accessKey` + `appSecret` 的 HMAC-SHA256 签名鉴权、时间戳防重放、IP 来源白名单与 QPS 令牌桶限流。
- **去除账号维度的强制领域绑定**：业务领域由表名与表注释自表达，开放接口不再强制要求必传 `domainCode`。
- **支持单账号绑定多个数据源库**：账号权限结构扩展为多库映射，单个 API 账号可同时授权访问多个物理数仓库（如 `datax_final`, `beidou_dw` 等）。
- **库表联动列表勾选授权控制**：在管理界面中，管理员为账号勾选数据源库后，直接异步拉取该库所有表及中文注释，支持表名/注释检索、一键全选（*）与列表逐行复选框细粒度勾选授权。
- **获取授权库表元数据接口**：根据当前账号实际被授权的数据库与表清单，脱敏返回表名、表中文注释、字段名与字段类型注释，自动过滤未授权表及系统内部库表。
- **多库 AST 语法树安全只读 SQL 执行接口**：接收外部 AI 提交的 SQL 与目标 `datasourceId`，采用 AST 语法树递归解析所有物理表并校验目标库表白名单，强制物理只读、10 秒超时中断与最大 1000 条截断。
- **数仓跑批中间态防脏读门禁**：校验底层批次就绪状态表（`latest_ready_date`），批次未计算完成前阻断查询。
- **可视化 API 账号与权限管理界面（Tab 8）**：智能助手中新增管理 Tab，包含账号生命周期管理（新增、编辑、删除、重置密钥、启停）与多库多表列表勾选授权面板。
- **调用日志与安全审计界面**：支持多维度（账号、状态、时间范围）检索调用记录，提供弹窗透视查看执行 SQL 语法详情、涉及表、耗时、返回条数与拦截报错原因。
- **系统菜单与管理端 CRUD 接口**：新增后台管理控制器 `/api/open/admin/**` 支持多库权限保存与日志检索，并同步在平台基线追加菜单与数据表演进 SQL。

## Capabilities

### New Capabilities
- `warehouse-open-api`: 外部系统与 AI 平台的数仓开放 API 能力，涵盖凭证验签网关、多库表元数据按权限分发、AST 语法树安全审计 SQL 执行、物理只读保护与防脏读门禁。
- `open-api-manage-ui`: 智能助手内的可配置化 API 账号权限管理与调用日志审计界面，提供账号多库绑定、交互式表列表勾选授权、调用日志检索与 SQL 透视。

## Impact

- **数据模型演进**：`job_api_account` 扩展 `permissions`（JSON 格式，保存多库与表授权清单映射），同时向前兼容 `datasource_id` 和 `allowed_tables`。
- **控制器与服务演进**：
  - 开放接口端：`JobOpenApiController` 去除 `domainCode` 必传校验，升级元数据与 SQL 执行的多库表鉴权。
  - 管理端：`JobOpenAdminController` 支持接收与返回多库授权映射。
- **前端组件重构**：
  - 重构 `static/static/js/assistant/tabs/tab8_open_api.js` 的新增/编辑弹窗，移除业务领域输入框，新增多数据源选择与表列表检索勾选交互组件。
- **数据库演进基线**：在 `bin/db/datax_web_stat_task.sql` 追加 `permissions` 字段定义与初始数据升级 SQL。
- **向下兼容**：完全向下兼容原有单一数据源调用方式与历史记录。
